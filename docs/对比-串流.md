# 和"串流 / 远程桌面"有什么区别

> 一句话：**串流把电脑屏幕搬到手机上；这个把 AI 的活儿留在电脑上，只把结论和过程搬回手机。**

## 逐项对比

| 维度 | 串流（Moonlight / Parsec / ToDesk / 向日葵） | DSH Helm |
|---|---|---|
| **传什么** | 屏幕像素（H.264/HEVC 视频流）+ 回传触控 | 语义事件：文本、工具调用、文件路径（几十 KB/s） |
| **带宽** | 5–50 Mbps，看分辨率与帧率 | 正常几十 KB/s；只有看图片/视频时才传媒体 |
| **延迟要求** | 必须 <50ms，否则点不准、拖不动 | 秒级都行 —— 本来就是异步任务 |
| **屏幕适配** | 1080p 压到 6 寸屏，字小到要双指放大；或被迫改电脑分辨率 | 原生 iOS 布局：气泡、折叠块、产物清单卡都为手机重排过 |
| **输入方式** | 虚拟鼠标/键盘，或拿手机当触控板 | 原生输入框、长按菜单、状态栏 |
| **能操作什么** | **整台电脑**：任何窗口、任何 App、文件管理器 | **只有 DSH 的会话控制**：发指令、审批、看产物 |
| **怎么改东西** | 亲手改（拖鼠标、敲键盘） | 审阅 → 一句话让它改（"这段拆出去""参数改成 30"），改完再验收 |
| **安全面** | 大 —— 等于把整机交出去（能开浏览器、看相册、改设置） | 小 —— 只有会话接口 + 文件白名单；`/admin` 只允许本机 |
| **断线** | 断了就断了，重连 = 重新看屏幕 | 带 `since` 补帧；丢失时会明确提示「离线期间有 N 条未送达」 |
| **耗电/发热** | 持续视频解码，手机烫、掉电快 | 文本渲染，基本无感 |
| **后台跑任务** | 手机离开就看不见（电脑还在跑） | 一样，但回来能看到**完整过程记录**（折叠块 + 过程页） |
| **跨网** | 通常自带穿透/中继（这是它方便的地方） | 默认只能同一 WiFi；跨网要自己配 Tailscale |

## 各自更擅长什么

**该用串流**

- 你要操作**具体 GUI**：改 Excel、修图、用 IDE、点某个软件里的按钮
- 你需要看整个桌面才能判断（排版、颜色、窗口布局）
- 你在外面，且不想配任何组网（商业串流有中继）

**该用 DSH Helm**

- 你要的是「**让 AI 替我干活，我只下指令和验收**」
- 你不想在 6 寸屏上找鼠标、缩放 1080p 画面
- 你在意「别把整台电脑的控制权暴露出去」
- 你想看见**过程**：它读了什么文件、跑了什么命令、第几步出错

## 一个容易被忽略的差别

串流给你的是**屏幕状态**，你得自己盯着看它跑完没有。
这个给你的是**结构化过程**：哪一轮、几步、每步参数与结果、产出了哪些文件 ——
跑完能直接验收，甚至能「打回重做」。

> 串流解决「看得见」，它解决「看得懂」。

## 诚实说它的短板

- **不能亲手改**（没有编辑器、没有画笔）：但**可以审阅内容并让 DSH 改** ——
  看 diff / 看产物 → 一句话"把这里拆出去""参数改成 30""重新裁 60 秒" → 它改完再验收
- 手机端能做的「操作」只限 DSH 暴露的能力，不是通用遥控
- 跨网不如商业串流省事（要自己配 Tailscale）

## 那"改东西"到底怎么改

这可能是最容易误解的一点：**它不是一个只读的监视器。**

| 你想做的事 | 怎么做 |
|---|---|
| 看它改了什么 | 每轮结束有折叠块，点开是完整过程；代码改动会带 diff 摘要 |
| 觉得不对 | 长按回复 → 引用到输入框 → 写"这里不对，应该…" → 发出去，它接着改 |
| 让它换个做法 | 直接说"换个方案，别用 ffmpeg 抽帧" |
| 只改一个文件 | 把那个文件转发给另一个会话，让它专注改这一个 |
| 改完想验 | 产物回到清单卡，图片能直接看、能标注，文件能下载 |

也就是说：**手上不动刀，但嘴上能指挥刀。** 真需要手动编辑的地方（改一行 CSS、画个圈），
才需要串流或回电脑。

## 能不能一起用

能，而且不冲突：

- 平时用 DSH Helm：下指令、看过程、验收产物（省电、省流量）
- 遇到「必须亲手改一下」的时刻，切串流进桌面操作
- 两者都指向同一台电脑，互不影响
