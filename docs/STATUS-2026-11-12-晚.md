## 三、没做完的 / 已知问题

### 1. 上拉加载更早的消息（正在做，未验证）

代码已经完整实现，但**滚动位置是否正确还没在真机确认**。

- 桥：`/v1/transcript` 支持 `?before=N`，返回 `hasMore` / `nextBefore`
- 手机：`loadOlder` 用游标分页、按 id 去重
- `ChatList.apply()` 在 completion 回调里补偿 contentOffset

**如果还是回到底部**，下一手应该换方案：
`UICollectionViewDiffableDataSource` 的 `apply` 哪怕带 completion，
偏移恢复也可能被后续 `layoutIfNeeded` 覆盖。更可靠的是
**增量 `insertItems`**（不重建 snapshot），或直接用 `UICollectionView` 的
`performBatchUpdates` 自己控制前后 contentSize 差值。

**别再靠调参数试**——我今天在这上面失败了 4 次，都是因为没有真机、
纯靠猜 UIKit 时序。

### 2. `mark=body` 仍有 1.2~1.8 秒停顿

拆 store 只做了三个（ChatStore / ComfyStore / WalletStore）。
`AppModel` 还有 23 个 `@Published`，任何一个变化都让 ChatView 重算。
继续拆的方向：ConnectionStore（phase / pairing / serverInfo / lastError）、
SettingsStore（exp* / sendMode / richTextEnabled）。

### 3. 余额只有兜底显示

`getBalance(client)` 需要传 client 对象（`version` / `locale` /
`timezoneOffsetSeconds`），已经补上。但**能不能真拿到数字**还没确认——
如果 DSH 那边还有别的初始化依赖，就维持现在的「已登录 + 用量页链接」。

### 4. 视频封面从来没触发过

`poster`（ffmpeg 抽帧）代码在，日志里一次都没出现过 —— 因为一直没滑到
视频消息。不是 bug，是没测到。

## 四、已经踩过、别再踩的坑

### 接口不确定就逆向（AGENTS.md §7）

`updateQueue` 我猜了七轮参数形状（target/start/removedCount/inserted、
六种变体、target 传对象……），全报同一句
`Cannot read properties of undefined (reading 'kind')`。

真相：读 `app.asar` 里的 zod schema，三分钟就看到

```js
updateQueue({ sessionId, itemId, action: { kind: "edit"|"remove"|"steer" } })
```

**猜七轮 ≈ 两小时 + 用户十几次点击；读源码 3 分钟。**

### 布局改动必须先想清楚约束会不会打架

气泡间距失败的原因是两个 top 约束同时生效：
`topConstraint`（可变）+ `stack.topAnchor == contentView.topAnchor`（固定 0）。
改之前读一遍整个约束块，就能发现。

### 拆分 store 必须检查所有订阅者都注入了

`WalletStore` 拆出去后 `SettingsView` 声明了 `@EnvironmentObject` 但
`MainView` 没注入 → **点设置页直接闪退**。编译期查不出来。

检查方法：把所有 `@EnvironmentObject var x: T` 和
`.environmentObject(...)` 列出来比对。

### configure 阶段 bounds 还是 0

气泡宽度按 `contentView.bounds.width` 算 → 那时是 0 → 宽度 0 →
**文字全被裁掉**（表现是「历史消息全看不见」）。
必须在 bounds 为 0 时退回屏幕宽度兜底。
