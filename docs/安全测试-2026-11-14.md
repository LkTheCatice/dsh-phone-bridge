## 三、待修问题

### P1 高：`/admin/*` 只靠 loopback 做边界，且 CORS 是 `*`

证据（实测）：

```
POST http://127.0.0.1:8765/admin/settings   {"autoApprove":true}   → {"ok":true,"autoApprove":true}
GET  http://127.0.0.1:8765/admin/devices    → 设备指纹、stateDir、端口、lanHost 全部可读
响应头  access-control-allow-origin: *
```

影响：任意网页（用户打开一个恶意页面即可）能
1. 读设备指纹与路径（信息泄露）
2. 打开 `autoApprove` → **绕过设备闸门**，任何拿到 token 的人都能直接建会话
3. 批准/移除设备、旋转 token（后者会让手机立刻掉线 = DoS）

**已修（待重启生效）**：`/admin/*` 现在要求请求头 `x-dsh-admin: 1`。
浏览器跨域发自定义头要先过预检，而预检允许的 headers 里没有它 → 网页发不出来；
本机插件面板（`bridge/client.js`）已同步带上这个头。

### P2 中：`/v1/diag` 无鉴权

localhost 上任何人（任意本地进程、任意网页的可读请求因 CORS `*`）都能拿到：
会话数、帧统计、`clients` 数、uptime、版本。

建议：和 `/v1/state` 一样要求 token；或至少不再返回 `clients` / 帧直方图。
（暂未改——iOS 端连上时会用它做健康检查，要先确认调用方再改。）

### P3 低：没有速率限制

连续 15 次错误 token 全是 `401`，无锁定、无退避。
token 是 43 字符随机串，暴力破解不现实；风险是日志灌注与少量资源消耗。
建议：`/v1/handshake` 按 IP 做 1 分钟 10 次的上限，超出返回 429。

### P4 低：`/admin/debug/env` 暴露环境细节

返回 `homedir`、`dshHome`、`sessions` 根、`logIndexSize`。本地排障有用，但属于不必要暴露。
建议：只在本机 + `x-dsh-admin` 头时返回（已随 P1 一起加上头要求）。

### 说明：20MB 请求体

`/v1/fs/write` 允许 20MB（返回 200）——这是**设计如此**：文件写入走分块，上限是 `maxFileBytes`（512MB）。
JSON 类端点单独限制 16MB（`MAX_JSON_BYTES`），两者不冲突，不是漏洞。

### P0：`bridge.log` 里写进了系统提示词原文

```

```

后果：只要有人把 `bridge.log` 发给别人（排障、反馈），就等于泄漏了整套私有指令集，
以及会话标题、产物文件的绝对路径（例如桌面「千问1生图」里的图片名）。

**已修**
1. 探针**只记形状、不记内容**（对象 → 仅列出键名；数组 → 仅长度）
2. 这段探针默认**不落盘**，只有 `DSH_PHONE_DEBUG=1` 时才写
3. 已就地清理历史日志：删掉 78 行含提示词的记录（1.95 MB → 1.63 MB），残留 0

### P1：`/v1/diag` 匿名可读（已修，待重启）

配合响应头 `access-control-allow-origin: *`，任何网页都能读到：
会话数、帧直方图、在线客户端数、uptime、版本。

**已修**：`/v1/diag` 现在要先过 token（iOS 端代码里没有调用它，不影响手机）。

## 二、本轮又补的两处

### 1) `/v1/health` 收窄（隐私）

以前匿名返回 `sessions`（会话总数）、`lastSeq`、`phoneOnline`。
这个端点**不需要 token**，响应头是 `access-control-allow-origin: *`，
等于任何网页都能探到"这台机器上有多少会话、手机在不在线"。

token 是 43 字符随机串，这不是防爆破，是防**日志灌注 / 白跑 CPU**

⚠️ 这两项都需要**再重启一次 DSH** 才生效；当前进程仍是旧代码，

| 认证失败无限速 | 同来源 60s 内 20 次 → 429 | 上一轮已加，随重启生效 |

## 二、明确不做的一项，以及为什么

**没有给 `pair.json` 上 DPAPI 加密。**

- DPAPI 挡的是"文件被拷走"（云备份、U 盘、发文件），但**同账户的其它程序照样能解**
- 代价却很大：换 Windows 账户 / 换机器后解不开 → 手机必须重新配对
- 收紧 ACL 没有这个失败模式，收益/风险比更好

如果以后确实要防"文件被拷走"，正确做法是 **BitLocker/EFS 覆盖 `~/.dsh`**，那是系统层的事。

## 三、修不了的一项

**DSH 自己的会话日志（`.jsonl.zstd`，58 个文件）是压缩不是加密。**

这不是手机桥的代码，是 DSH 的存储格式。桥侧能做的最多是"读完就删缓存"，
没有意义。真正能覆盖的场景只有一个：整盘加密（BitLocker）。
