## 三、待修问题

### P1 高：`/admin/*` 只靠 loopback 做边界，且 CORS 是 `*`

证据（实测）：

```
POST http://127.0.0.1:8765/admin/settings   {"autoApprove":true}   → {"ok":true,"autoApprove":true}
GET  http://127.0.0.1:8765/admin/devices    → 设备指纹、stateDir、端口、lanHost 全部可读
响应头  access-control-allow-origin: *
```

影响：任意网页（用户打开一个恶意页面即可）能
1. 读设备指纹与路径（信息泄露）
2. 打开 `autoApprove` → **绕过设备闸门**，任何拿到 token 的人都能直接建会话
3. 批准/移除设备、旋转 token（后者会让手机立刻掉线 = DoS）

**已修（待重启生效）**：`/admin/*` 现在要求请求头 `x-dsh-admin: 1`。
浏览器跨域发自定义头要先过预检，而预检允许的 headers 里没有它 → 网页发不出来；
本机插件面板（`bridge/client.js`）已同步带上这个头。

### P2 中：`/v1/diag` 无鉴权

localhost 上任何人（任意本地进程、任意网页的可读请求因 CORS `*`）都能拿到：
会话数、帧统计、`clients` 数、uptime、版本。

建议：和 `/v1/state` 一样要求 token；或至少不再返回 `clients` / 帧直方图。
（暂未改——iOS 端连上时会用它做健康检查，要先确认调用方再改。）

### P3 低：没有速率限制

连续 15 次错误 token 全是 `401`，无锁定、无退避。
token 是 43 字符随机串，暴力破解不现实；风险是日志灌注与少量资源消耗。
建议：`/v1/handshake` 按 IP 做 1 分钟 10 次的上限，超出返回 429。

### P4 低：`/admin/debug/env` 暴露环境细节

返回 `homedir`、`dshHome`、`sessions` 根、`logIndexSize`。本地排障有用，但属于不必要暴露。
建议：只在本机 + `x-dsh-admin` 头时返回（已随 P1 一起加上头要求）。

### 说明：20MB 请求体

`/v1/fs/write` 允许 20MB（返回 200）——这是**设计如此**：文件写入走分块，上限是 `maxFileBytes`（512MB）。
JSON 类端点单独限制 16MB（`MAX_JSON_BYTES`），两者不冲突，不是漏洞。
