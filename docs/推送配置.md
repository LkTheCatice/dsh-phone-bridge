# 手机推送（Bark / ntfy）配置说明

用途：**手机不在前台时**，DSH 里的提问要能被推送叫醒。

iOS 不允许第三方 App 在后台保持长连接，所以 App 被挂起后收不到任何实时消息。
唯一可靠的办法是走苹果的推送通道 —— 而往 APNs 发消息必须有一个服务。
Bark / ntfy 就是现成的、免费的推送服务。

---

## 一、Bark

### 该装哪个

App Store 里叫 "Bark" 的有好几个，**要装的是开源推送客户端**：

- 仓库：`github.com/Finb/Bark`
- App Store 名称类似 **「Bark - 给你的手机发推送」**
- **免费，没有订阅、没有内购**
- 应用说明里会出现这些字样：
  - `https://api.day.app/`
  - 「自定义推送」「HTTP API」
- 打开后首页有：
  - 一串 **设备 key**（20 位左右的字母数字）
  - 一个「复制推送地址」按钮
  - 服务器地址设置（默认 `api.day.app`）

### 不要装哪个

| 名字 | 是什么 | 为什么不是它 |
|---|---|---|
| **Bark — Parental Controls** | 美国的家长监控 App（Bark Technologies） | 要订阅，跟推送无关 |
| **Bark 狗叫训练 / Dog Barking** | 训狗、狗叫录音 | 完全无关 |
| **Bark: Dog Translator** 之类 | 玩具 App | 无关 |

判断依据很简单：**要看订阅、要注册账号的都不是它**。正确的那个打开就能用，不用登录。

### 装完怎么拿 key（三步）

1. 打开 App，首页顶部就是设备 key
2. 点「复制推送地址」，会得到形如 `https://api.day.app/XXXXXXXXXXXX/`
3. 把 `XXXXXXXXXXXX` 那段发我

### 自建服务器（可选）

Bark 支持自建服务端（`github.com/Finb/bark-server`），配置里填 `server` 即可：

```yaml
notify:
  kind: bark
  server: https://你的域名
  key: 你的 device key
```

## 二、ntfy

### 该装哪个

- App Store 搜 **ntfy**，开发者 Philipp Heckel
- 开源（`github.com/binwiederhier/ntfy`），免费，无订阅
- 图标是绿底白色 `ntfy` 字样

### 装完怎么配

1. 打开 App → 右下角 `+` → 订阅 topic
2. topic 名**自己起一个难猜的**（例如 `yg-dsh-7k2px9`）—— 默认服务器上任何知道这个名字的人都能读到
3. 把 topic 名发我

配置：

```yaml
notify:
  kind: ntfy
  key: yg-dsh-7k2px9
  topic: yg-dsh-7k2px9
```

### 自建服务器

```yaml
notify:
  kind: ntfy
  server: https://你的域名
  topic: 你的 topic
  key: 你的访问令牌
```

## 三、隐私边界（要清楚）

| 走谁的服务器 | 内容 |
|---|---|
| `api.day.app`（Bark 官方）或 `ntfy.sh` | **推送标题和正文会经过它**，明文 |
| 你自己的服务器 | 自己承担 |

推送正文只放**问题的第一句**（由桥截取），不放会话全文、不放文件内容。

不想让任何第三方看到内容：
- 自建 bark-server / ntfy，或者
- 不配推送 —— 那就退化成"必须开着 App 才能收到提问"

---

## 四、配好之后的行为

| 情形 | 桥的行为 |
|---|---|
| 手机在前台 | 直接推给 App，不推送 |
| 手机切后台（SSE 还连着） | 8 秒没人答 → 推送；最多再补 2 次（60s / 120s） |
| 手机锁屏 / App 被杀 | 推送 + 保留问题 2 分钟，等你开 App 回答 |
| 2 分钟还没答 | 交回电脑，手机上的卡片收起并标记「已交回电脑处理」 |

窗口长度可在桥配置里调：

```yaml
ask:
  holdOnlineMs: 600000   # 手机在线时等多久（默认 10 分钟）
  holdPushMs: 120000     # 靠推送唤醒时等多久（默认 2 分钟）
```
