
为此做了两层拆分（都进了 `Core/`，纯 Foundation）：
- `MarkdownModel.swift`：`Block` / `MarkdownParser` / `InlineParser`
- `MediaRefScan.swift`：媒体路径扫描 + `MediaRefs` + `MediaRefCache`

### 二、行内富化回归（用结构性方案，不是打补丁）

之前因为「多轮 `replaceCharacters` 导致 NSRange 失效 → 点开就闪退」把行内富化整个砍了。
现在换成 **`InlineParser` 扫描式分段**：只读原字符串、只产出 `[(text, style)]`，
iOS 侧只做 `append`，**文件里已无 `replaceCharacters`**。越界从结构上不可能。

### 三、补回媒体可见性（重构造成的功能回退）

列表换 cell 后 `MessageCell` 只渲染文本，图片/视频/音频在列表里完全看不到。
按 AGENTS.md §0 处理：**媒体不进 cell**（不塞 `UIHostingController`），
cell 里只加一行「📎 N 张图片 · M 个视频，点按查看」，点开走 `AttachmentSheet`
复用现有 `RemoteImage`/`RemoteVideo`/`RemoteAudio`。滚动成本仍与内容无关。

### 四、markdown 开关默认改为开启

老渲染方式（一条消息 N 个 Text）一开就卡死，所以之前默认关。
现在管道是「一个 cell = 一个 UITextView = 一个 NSAttributedString」+ 扫描式行内，
打开是安全的。**注意：手机上如果之前手动关过，UserDefaults 会记住旧值**，
需要去「设置 → 诊断实验」手动打开，或重装。
