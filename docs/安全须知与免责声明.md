## 一、这是什么，能做什么

它把 iPhone 变成 DeepSeek Harness 的**遥控器**：手机发一句话，电脑上真实执行（跑命令、改文件、调工具），过程与产物回流到手机；动手前需你在手机上点确认。

**关键事实（决定了风险边界）**：

| 事实 | 含义 |
|---|---|
| 执行发生在**你的电脑**上 | 模型的每一步都有你电脑的真实权限（能读写文件、跑命令） |
| 手机是**远程输入装置** | 手机丢了 ≈ 遥控器丢了，见第五节 |
| 传的是**你的私人会话与文件** | 里面可能有客户资料、密钥、聊天记录 |

## 二、安全模型（三层，缺一不可）

```
① 网络层  只有同一局域网可达；/admin 只允许本机回环
② 鉴权层  配对 token（43 字符）+ 设备指纹闸门（未批准设备连 e2ee 都不建立）
③ 应用层  X25519 + AES-256-GCM 端到端加密，AAD 绑定方法与路径（防重放/跨端点）
```

在此之上：文件访问有**根目录白名单**（realpath 校验，符号链接逃逸、`..` 穿越、NTFS 备用流都会被拒）。

> 三层都经过实测验证，结论见[安全测试报告](安全测试-2026-11-14.md)：19 项检查，19 项通过。

## 三、你必须遵守的红线

1. **不要做公网端口映射**（不要把 8765 暴露到路由器/云服务器）。
   桥是 **HTTP 明文 + 应用层 E2EE**，没有 TLS。暴露到公网等于把配对令牌丢在互联网上。
   需要跨网访问时，用 VPN/组网（Tailscale、WireGuard），别做 DNAT。
2. **不要把 `pair.json` 发给任何人**，也不要提交进 Git。
   它含配对 token 与服务器私钥，泄露 = 任何人可冒充你的设备。
3. **不要关闭 `requireE2ee`**。关掉之后会话内容走明文 HTTP。
4. **`roots` 只加具体目录，不要加盘符根**（`D:\`、`C:\` 都不行）。
   白名单越宽，"模型误删/误改"的爆炸半径越大。
5. **不要在不信任的电脑上跑**。桥拥有该电脑的完整文件与命令权限。
6. **`askPhone` 保持开启**（工具调用前需你确认），除非你明确知道自己在关掉什么。

## 四、已知限制（明确告诉你，别指望它没有）

| 限制 | 说明 | 缓解 |
|---|---|---|
| **静态数据未加密** | 会话日志（`.jsonl.zstd`）只压缩不加密；`pair.json` 是明文 JSON | 开 **BitLocker** 覆盖 `~/.dsh`；`pair.json` 已收紧 ACL |
| **同账户程序可读** | ACL 只拦其它 Windows 账户；同账户的恶意程序照样能读 | 不要在这台电脑上装来路不明的软件 |
| **日志含路径** | `bridge.log` 会记录文件绝对路径 | 对外发送前设 `DSH_PHONE_LOG_MIN=1` 并重启 |
| **无速率硬防护** | 只有"60 秒 20 次失败 → 429"的软限速 | token 是随机 43 字符，爆破不现实 |
| **App 是自签名侧载** | 免费签名 **7 天过期**，过期后打不开 | 到期重签重装；不要用于生产 |
| **依赖局域网** | `lanHost` 是固定 IP，换网络后手机连不上 | 换网络后改配置并重启 DSH |
| **无多用户隔离** | 单用户设计，不做权限分级 | 不要多人共用同一台电脑的同一个账户 |

## 五、你的责任

1. **设备安全**：手机设锁屏密码、开启"查找"；丢失后立即在电脑端「设置 → 手机设备」里**拉黑/移除**该设备，并**轮换 token**（`/admin/rotate-token`）。
2. **电脑安全**：系统补丁、磁盘加密、不要在公用电脑上部署。
3. **数据备份**：本工具的"删除/覆盖"是**真实删除**，没有回收站。重要文件先备份。
4. **合规使用**：你用它处理的数据（客户资料、个人信息、商业机密）由**你**负责取得授权并遵守当地法律（如《个人信息保护法》《GDPR》）。不要用它处理你不被允许处理的数据。
5. **模型行为的复核**：模型会犯错，会自信地给出错误结论。**关键操作（删文件、发布、转账、对外发送）必须人工复核。**

## 七、怀疑泄露时怎么做（事件响应）

```powershell
# 1) 立刻断开手机的访问权
#    电脑端：设置 → 手机设备 → 该设备「拉黑」（或 POST /admin/devices/status {"status":"blocked"}）

# 2) 轮换 token（手机需要重新配对）
curl -X POST http://127.0.0.1:8765/admin/rotate-token -H "x-dsh-admin: 1"

# 3) 检查谁在连
curl http://127.0.0.1:8765/admin/devices -H "x-dsh-admin: 1"

# 4) 清日志（含路径与操作痕迹）
#    <stateDir>\bridge.log 与 bridge.log.1

# 5) 若怀疑密钥外泄：删除 <stateDir>\pair.json 后重启 DSH（会生成新 token，所有设备需重新配对）
```

补充：如果泄露的是**会话内容**（而不是 token），token 轮换没用 —— 内容已经在你电脑上，要按数据泄露事件处理（评估影响范围、通知相关方）。
