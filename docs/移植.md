# 移植到另一台电脑 / 另一台手机

目标是：**换机器后只改配置，不改代码**。下面按「必备 → 配置 → 验证」排。

## 0. 前置

| 项 | 要求 |
|---|---|
| 系统 | Windows 10/11（桥用到了 `icacls`；macOS/Linux 下自动跳过） |
| Node | **24+**（桥用 `node:zlib` 的 zstd，低版本读不了会话日志） |
| DSH | 桌面版，能加载本地插件 |
| 手机 | iOS，可用 Sideloadly / AltStore 侧载（免费签名 7 天） |
| 开发机（可选） | 本机 Swift 工具链（只用来跑 `swiftc -parse` 和 selftest；**不需要 Xcode**） |

## 1. 代码放哪都行

仓库不假设自己的位置，唯一要求是：**安装脚本要在仓库根下执行**。

```powershell
cd <你的仓库>\phone-dsh
powershell -ExecutionPolicy Bypass -File bridge\install.ps1
```

它会：
1. 在 `%USERPROFILE%\.dsh\profiles\desktop\node_modules\` 下建一个**指向当前仓库**的软链
2. 把插件配置片段写进 `cordis.patch.yml`
3. 打印接下来要做的两步（重启 DSH、扫码配对）

> 移动或重命名仓库之后，重跑一次 `install.ps1` 即可修好软链。

## 2. 配置项（只有这几处，都在 `cordis.patch.yml`）

```yaml
- insert:
    - id: phone-bridge
      name: dsh-phone-bridge
      config:
        port: 8765
        lanHost: "192.168.1.23"        # ← 换成这台电脑的局域网 IP；留空则只监听本机
        askPhone: true                  # 手机端是否要确认工具调用
        approvalTimeoutMs: 90000
        requireE2ee: true               # 必须保持 true
        stateDir: '<放 token/密钥/log 的目录>'   # 建议 <仓库>..\dsh-phone-bridge 或 %USERPROFILE%\.dsh\phone-bridge
        roots:                          # 手机**允许读写**的根目录，按需增删
          - '<你的产物目录，例如 D:\output>'
        notify:                         # 完成通知（可选，留空=不出网）
          kind: ""
          server: ""
          key: ""
```

`lanHost` 用这条命令查：

```powershell
(Get-NetIPAddress -AddressFamily IPv4 | Where-Object { $_.IPAddress -notmatch '^127\.' }).IPAddress
```

**`roots` 只加具体目录，不要开盘符。** 白名单之外的路径一律 403（已测）。

## 3. 首次配对

1. 重启 DSH
2. 手机 App → 设置 → 扫码（DSH 设置页 →「手机设备」里有二维码；或跑 `node bridge\bin\pairing.mjs`）
3. 电脑端「设置 → 手机设备」点**允许**（`/admin/devices` 也能看到这台设备）
4. 手机健康检查应显示「已连接」

## 4. 验证清单（换机器后逐条跑）

```powershell
cd <仓库>\phone-dsh

# ① 语法（不需要 Xcode）
powershell -File tools\selftest\run.ps1          # 188 项断言

# ② 安全 + 隐私（需要先批准测试设备，见 tools/pentest.mjs 顶部注释）
node tools\pentest.mjs --gen
#   批准打印出来的 fingerprint 后：
node tools\pentest.mjs --run      # 19 项，应全 PASS
node tools\privacy-audit.mjs

# ③ 桥的健康
curl http://127.0.0.1:8765/v1/health
```

## 5. 打 IPA（不需要 Mac）

`.codemagic.yaml` 已配好「无签名 IPA」工作流：

```powershell
# 需要 Codemagic 的 API token，放在 %USERPROFILE%\.codemagic-token
$env:HTTPS_PROXY="http://127.0.0.1:7892"   # 若本机要走代理（curl 不读系统代理）
node tools\build-ipa.mjs                    # 或按 docs/侧载.md 里的一步步来
```

## 6. 仍需人工确认的“隐性绑定”

| 位置 | 绑定什么 | 换机器时怎么处理 |
|---|---|---|
| `bridge/index.js` → `detectExtraRoots()` | 现在只认 `DSH_PHONE_ROOTS` 环境变量与 `~/.dsh/storages/phone-roots.json`（不再内置任何目录） | 换机器时把产物目录写进这两处即可 |
| `cordis.patch.yml` → `lanHost` | 当前局域网 IP | 换网络后在设置页改 |
| `~/.codemagic-token` | Codemagic API | 换机器需重新生成 |
| Codemagic 应用 ID | `.codemagic.yaml` / 脚本里的 `appId` | 换账号要改 |
| 免费签名证书 | Sideloadly 里的 Apple ID | 每台手机各自的 |

## 7. 数据在哪（备份 / 迁移）

| 内容 | 路径 | 说明 |
|---|---|---|
| token + 服务器私钥 | `<stateDir>\pair.json` | 搬走后 ACL 会失效，建议重新配对 |
| 桥日志 | `<stateDir>\bridge.log`（+`.1`） | 含路径，发出去前 `DSH_PHONE_LOG_MIN=1` |
| 设备指纹/批准状态 | `pair.json` 的 `clients` | 一起搬则不用重新批准 |
| 会话内容 | `%USERPROFILE%\.dsh\sessions\**` | **属于 DSH 本体**，不是本项目的 |

## 8. 已知的“不适合直接搬”的东西

- `pair.json` 被 ACL 收紧成「原账户 + SYSTEM」，换 Windows 账户后桥会读不到 → 重新配对
- 会话日志是按**工作区路径**分目录（`--D-Documents-...--`），换盘符后历史会“消失”（其实在旧目录名里）
- 手机端 App 的 bundle id 固定，换 Apple ID 侧载需要重新签名
